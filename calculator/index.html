Why a budgeting app ships a real calculator

Most finance apps bolt on a basic four-function calculator as an afterthought. This one is different: it's the same "AI Engineer Calculations" engine used to verify the app's own budgeting math, opened up as a real, general-purpose scientific calculator — kinematics and Newton's laws, the ideal gas law, tensors and rotation matrices, CIE and OKLCH color science, even a frequency-to-color mapping for audio. Every function has a citation, every function has a test, and every function is computed the same exact way whether you're on the Python backend or the iOS app itself.

Cited, not guessed

Every constant traces to a real source — NIST CODATA, published academic transforms, standard textbook derivations — never a remembered number.

Cross-language parity

Each domain ships a golden-vectors test file: the Python reference computation is checked against the Swift implementation on your phone, to a stated numeric tolerance.

Free, every tier, every language

Not a premium feature. Not gated behind a subscription. It ships free because a genuinely useful tool shouldn't be a paywall bargaining chip.

Built on a real precision standard

Every one of these engines runs in IEEE 754 double precision (binary64) — the same 64-bit format used by Python's native float and Swift's native Double by default. That's a deliberate choice, verified rather than assumed:

PropertyValueWhat it means
Mantissa width53 bitsThe real bit budget for significant digits
Guaranteed decimal digits15Any number with ≤15 significant digits round-trips exactly
Machine epsilon2.220446049250313e-16The smallest gap between representable numbers near 1.0

In practice, that's roughly 15–17 significant decimal digits of usable precision — a step above a real, documented graphing calculator like the Texas Instruments TI-84 Plus/CE line, which runs a fixed-point format at 14 significant digits internally.

This precision tier is deliberately kept separate from money math: every dollar figure in the app — budgets, balances, cost-of-living data — uses exact decimal arithmetic instead, because IEEE 754 binary floats can't represent most decimal fractions exactly (the textbook case: 0.1 + 0.2 ≠ 0.3 in double precision). A budget rounds exactly; a physics calculation runs in the format built for it. Two different jobs, two purpose-fit tools.
